# RG-20260704-05 — Video + camera bake playback sync plan review

## 親の目的（1–3 文）
編集中プレビューで、映像 Footage とモーショントラックでカメラにベイクされた動きが再生時にズレる（モーションが早すぎる）問題を直す。スクラブ応答性は壊さず、再生ボタン押下時に同期して再生したい。プラン [`.cursor/plans/video_camera_playback_sync.plan.md`](../../plans/video_camera_playback_sync.plan.md) の推奨経路 H（Play-start barrier + timeline hold）をレビューし、実装前に穴・代替・受け入れ条件を固める。

## 確定事項
- §5 / INV / `project.json` は変更しない（preview 時計のみ）。
- scrub / export の seek 方針は触らない（レスポンス・INV-2）。
- 再生中の drift seek 閾値 `PLAYBACK_RESYNC_THRESHOLD_SEC = 0.5s`（対策 A・旧 HW スタッタ防止）は維持。映像を seek でタイムラインに引っ張らない。
- 真因仮説: カメラ = `resolve(frame)`（タイムライン時計）、映像ピクセル = `video.play()`（メディア時計）。再生中は最大 0.5s まで seek しないためカメラが先行し「モーションが早すぎる」。
- 推奨経路 H: (1) Play 時 `syncMountedVideosForPlay`（primed キャッシュ無視）→ `previewVideoPlayback=true` で 1 回 render → clock 起動 (2) 再生中 `mafterTargetSec - currentTime` で遅れ検出 → timeline hold（rAF は frame 止め、AudioClock は suspend + origin 再ベース）。
- BundlePlayer は Phase 1 barrier のみ（hold は Preview 後）。
- Pass 1/2 二重チェックで逆写像を捨て lag 判定に簡略化済み。AudioClock の origin ジャンプ問題もプランに反映済み。
