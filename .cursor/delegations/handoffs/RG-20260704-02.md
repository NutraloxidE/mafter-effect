3. QUAR 並進は非メトリックスケールだが、range 0.1px はスケール以前に推定自体が死んでいる可能性。

## Handback

### 1. 根本原因ランキング（コードからの証拠つき）

**R1（主因）: 既定マスク「背景優先」が Comp 27 の追跡可能領域をほぼ全て黒塗りする。**
- `src/editor/panels/VideoComponentFields.tsx:83` — 既定 `roiPreset = "background"`。`trackRoi.ts:114-117` で `exclude: [{x:0.12, y:0.2, w:0.76, h:0.8}]` = x∈[12%,88%]・y∈[20%,100%]、**画面の 61% を黒塗り**。
- f001 を実際に確認: 「止まれ」路面標示・停止線・消失点・家屋前面 — 最良の KLT 特徴と前進パララックスの源泉が全部 exclude 内。残るのは上 20% 帯（曇天＋電線）と左右 12% 柱（640px 幅で各 ~77px）。
- 残存する実特徴（空・電線）は実質無限遠 → 前進ドリーでパララックスほぼゼロ。**マスク後の画には並進を観測できる情報が原理的に無い**。

**R2（position が「全 invalid」でなく「確信度つき微小値」になる機構）: QUAR 経路は点レベルのマスクフィルタを持たない。**
- マスクはピクセル黒塗りのみ（`frameExtractor.ts:143`）。回転経路だけが `filterPointsInRoiInterior`（margin 3px）で境界点を棄却し、QUAR worker にはマスク情報が渡らない。
- exclude 境界は全フレーム**完全静止・最大コントラスト**のエッジ。QUAR はこれにロックし「高確信度・並進ゼロ」を返し、`MIN_CONFIDENCE=1`（`quarTracker.ts:34`）を通過して valid になる。
- 全フレーム invalid なら `interpolateInvalidVec3Series` の fallback で range は**厳密に 0** のはず。0.11px≠0 は「valid だが実質ゼロの推定」が混ざる証拠。親仮説 3 の正確な姿は「**静止した偽特徴で、生きたまま死んでいる**」。

**R3（rotation が厳密に全ゼロになる機構）: 全フレーム invalid → baseline ホールドの無警告ベイク。**
- 回転経路は境界点を正しく棄却するので、候補は空（無特徴）と電線（細線 → aperture problem で FB 誤差 `FB_ERR_PX=1` 超過）だけ。`pairs>=4` / `MIN_INLIER_RATIO=0.2` / `MAX_RESIDUAL=0.08`（`quarTracker.ts:268-280`）を全フレーム満たせない。
- `buildRotationsFromTrack`（`quarTracker.ts:416-427`）は invalid を前値ホールド・初期値 `{0,0,0}` → **全フレーム厳密に identity**。「ゼロと推定した」のではなく「**一度も推定できず、それを知らせずベイクした**」。
- なお前進ドリー区間が rotation-only モデル（ノーダルパン前提）で invalid になるのは正しい挙動。問題はチルト区間まで全滅＋無警告。

**R4（副次）: `rotationTrackWorker.ts:255-268` の `equalizeHist` がマスク非対応** — 黒 61% がヒストグラムを支配し実画素のコントラストを圧縮（メインスレッドの `enhanceContrastRgba` はマスク対応済みなのに worker で台無し）。LK 失敗の増幅要因。

**問い 1 への回答**: 主因は背景優先マスクで十分。ただし R2・R3 が「失敗を成功に見せる」増幅器として実在し、R3 は独立に直す価値がある。QUAR confidence 閾値・コントラスト伸長・warmup は主因ではない。

### 2. 最小修正セット（実装順・今回の 1 本 = ①〜③）

1. **既定を `full` に** — `VideoComponentFields.tsx:83`、~567 行の説明文も「人が多いシーンでは『背景優先』を選択」に更新。
2. **rotation 全滅ガード** — ベイク前に valid 率判定（warmup 除外）。`validRatio < 0.3` なら警告表示＋confirm で **identity をベイクせずスキップ**（both モードは position のみベイク）。純関数 `summarizeTrackValidity(validMask, warmupFrames)` を新設し unit test。position 側も同関数で status に valid 率を出す。
3. **spec §16.1 散文更新＋テスト** — `doc/mafter-effect-spec.md:977` の「既定マスク『背景優先』」を「既定は『全体』、背景優先はオプトイン」に（散文のみ・§5/INV 非接触）。`test/motionTrackRoi.test.ts` 追随。
4. **（次点）`TRACK_EXCLUDE_CROWD` 縮小** — `trackRoi.ts:31` を `{x:0.15, y:0.35, w:0.7, h:0.6}` 程度（人混みの頭部は通常 y≈0.35 より下）。人混みシーンの回帰確認とセットでのみ。
5. **（次点）worker `equalizeHist` を `isFullMask` 時のみ適用** — 1 行分岐。

**問い 2**: Comp 27 には①だけでおそらく足りる。auto mask は人物検出器なしでは作れず今はやらない — ②のガードが安全網を兼ねる。
**問い 3**: 幾何は④の通り縮小しつつ、本質は「既定にしない」こと。プリセット自体は人混み用として存続。
**問い 4**: ②の通り「valid 率で検出 → 警告 → identity ベイクをスキップ」。150 個の identity KF を黙って焼く現状は既存 rotation アニメーションも破壊しうる。

### 3. Comp 27 受け入れ条件（測定可能・問い 5）

修正後の既定設定（full・同 userScale）で `for-debug-data/_pj17/` Comp 27 に combined track を再実行:

- **AC-1**: position validRatio ≥ 0.6（warmup 除外）。
- **AC-2**: 支配軸（前進なので z を期待）のベイク range ≥ 10px かつ旧結果（0.11px）の ≥ 50 倍。frame-to-frame ジャンプはスロープ制限内。
- **AC-3**: rotation validRatio ≥ 0.2、かつチルト遷移区間で max |rotation.x| ≥ 10°。ドリー支配区間の invalid ホールドは合格（正しい棄却）。純空フレーム（f011 近傍）の invalid も許容。
- **AC-4**: 人混みシーンで「背景優先」を明示選択した結果が悪化しない。`npm test` 緑。
- **AC-5**: rotation 全滅ケースで警告が出て identity 150KF がベイクされない。
- 計測: `probe-motion-spike*.mjs` パターンの Playwright 実ブラウザ駆動（headless 不可・port 5175）。ベイク後 KF を project.json から読み range/validRatio を機械判定するスクリプトを 1 本残す。

### 4. やらないこと

- §5 / `TrackOptions` / 直列化の変更（mask はセッション UI 状態のまま）。
- QUAR WASM 内部改変・GPL 導入。
- `MIN_CONFIDENCE` / `MIN_INLIER_RATIO` / `MAX_RESIDUAL` の緩和（原因ではなく、緩めると悪いシーンでゴミ回転が通る）。
- マスク境界フェザリング（ぼかしても静止特徴は静止特徴。QUAR では原理的に防げない — §16.1 に既知制約として散文追記が正解）。
- ML 人物検出 auto mask、smoothing / `interpolateInvalidVec3Series` 変更、「背景優先」プリセットの削除。
