# RG-20260710-01 — Static-noise bundle audio architecture review

## 親の目的（1–3 文）
HTML bundle のループ境界で video 内蔵音声がクリック／静的ノイズを出す問題を、bundle 専用の最小変更で安全に解消する。既存 fix-plan は Web Audio gain controller を提案しているが、DomRenderer の video プールと no-audio playback loop への配線が未確定である。

## 確定事項
- 再現: Downloads の `mafter-project (25).zip` / `Comp 10`。range `[0,112)` @30fps、video embedded AAC の 3.733333s→0 seek は非ゼロ PCM seam。
- 現状は `DomRenderer` が render 時だけ `video.volume = resolved gain` を書く。no-standalone-audio bundle は `runPreviewPlaybackLoop` + adaptive render gate を使い、最終描画が飛び得る。
- standalone audio は `BundleAudioClock` が別 `<audio>` 要素を管理するが、inPoint/outPoint/trimStart を正しく適用していない。
- §5、INV、project.json は変更しない。editor preview/export の挙動は変更しない。`src/player` / bundle player のみが対象。

## 未決・委任したい問い
1. Web Audio を採用するなら、DomRenderer がプールする video 要素へ安全に接続し、resolved user gain を render cadence と独立して反映し、loop seek が必ず無音中に行われる最小設計は何か。
2. video-only bundle と standalone-audio bundle の双方で、loop boundary callback をどの責務（`runPreviewPlaybackLoop` / `BundleAudioClock` / 新 controller）に置くべきか。async seek readiness と visual clock の関係も評価してほしい。
3. 現行 plan の危険点（autoplay, one source per element/context, pooled reuse, native `muted`/`volume`, seek 同期、二重音声）と、具体的な acceptance/verify を提示してほしい。
